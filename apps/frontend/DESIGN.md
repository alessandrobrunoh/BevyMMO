# Eivar Online — Web Design System

## 1. Project Vision

Eivar Online is a fantasy MMORPG centered around exploration, ancient magic, customizable weapons, runic inscriptions, Essences, Ancient Words, PvP, PvE, cities, factions, and a persistent online world.

The website must feel like an extension of the game itself.

It must NOT look like:
- a generic SaaS landing page
- a dark World of Warcraft clone
- a black/red hardcore RPG website
- a generic Bootstrap dashboard
- a futuristic sci-fi interface
- an overly ornate medieval parchment website
- a mobile-game cash shop

The visual identity should be:

- Fantasy
- Adventurous
- Ancient
- Mystical
- Clean
- Bright
- Slightly stylized / low-poly
- Premium but not luxurious
- Readable
- Modern
- Immersive

The provided Eivar Online cover artwork is the primary visual reference.

# 2. Visual Direction

## Main Reference

The Eivar Online key art contains:

- a huge blue sky
- stylized white clouds
- floating islands
- enormous ancient rock formations
- medieval fantasy cities
- mountains and cliffs
- vegetation
- blue magical energy
- ancient glowing runes
- banners
- warriors
- exploration
- a sense of enormous scale

The website should inherit those ideas.

The UI should feel like a civilization built inside this world rather than a web application placed on top of it.

---

# 3. Core Visual Language

## Shapes

Prefer:

- subtly irregular edges
- carved stone shapes
- restrained fantasy frames
- beveled corners
- angular rune-inspired details
- thin metallic separators
- geometric symbols
- slightly asymmetrical decorative elements

Avoid excessive roundness.

Do NOT make every component a rounded rectangle.

Recommended border radius:

- buttons: 3–6px
- cards: 4–10px
- modals: 6–10px
- images can have slightly larger radii where appropriate

Some fantasy panels can use clipped / chamfered corners.

# 5. Typography

The Eivar Online identity should use two typography families.

## Display / Headings

A fantasy serif inspired by carved lettering.

Characteristics:
- sharp serifs
- ancient feel
- strong uppercase appearance
- readable
- not gothic

Used for:
- H1
- major page titles
- hero sections
- section labels
- important cards

Potential visual direction:
Cinzel-like / Trajan-inspired fantasy serif.

Do not excessively letter-space long headings.

---

## Interface / Body

Modern readable font.

Characteristics:
- neutral
- clean
- excellent readability
- slightly humanistic

Used for:
- paragraphs
- navigation
- buttons
- wiki content
- store descriptions
- metadata

Ancient runes are one of the most recognizable visual elements of Eivar.

Rune motifs can appear as:

- section separators
- faint background decorations
- loading animation
- button hover effects
- active navigation indicator
- Wiki category symbols
- cards
- borders

Avoid random neon glyphs everywhere.

# 8. Texture

Use extremely subtle textures.

Possible materials:

- stone
- aged metal
- parchment
- rough paper
- carved rock
- fabric banners
- faint grain

Textures should usually stay between approximately 2–8% visual intensity.

The interface must remain clean.

# 9. Lighting

Use environmental lighting inspired by the cover art.

Common effects:

- soft blue ambient light
- subtle cyan magical glow
- warm sunset/gold highlights
- shadows with blue undertones
- slight atmospheric haze

Avoid huge glowing neon boxes.

# 23. Animation

Animation should make the world feel alive.

Use restrained motion.

Examples:

- slow hero parallax
- floating island background drift
- cloud movement
- rune glow pulse
- navigation transition
- card hover depth
- image scale on hover
- section reveal
- subtle particles
- button engraving illumination
- modal transition
- accordion animations
- dropdown animations

Animations should normally stay between 150ms and 500ms for UI interactions.

Environmental animations can be significantly slower.

Respect prefers-reduced-motion.

Do not overload the site with animations.

# 25. Accessibility

Required:

- keyboard navigation
- visible focus states
- semantic HTML
- labels
- alt text
- accessible modals
- sufficient contrast
- reduced motion support
- appropriate ARIA only where necessary

Fantasy aesthetics must never compromise usability.

# 27. State

There is NO application/backend state yet.

Only maintain local presentation/UI state such as:

- modal open/closed
- navigation menu
- active filter
- selected store item
- accordion
- search query
- tabs
- mock login form state
- toast notifications

Prefer simple Angular signals/local component state.

Do not introduce Redux/NgRx.

---

# 28. Mock Data

Keep fake content outside components.

Examples:

data/mocks/news.mock.ts
data/mocks/updates.mock.ts
data/mocks/wiki.mock.ts
data/mocks/store.mock.ts

Components should consume typed mock objects.

This allows future backend services to replace the mock data easily.

---

# 29. Backend Preparation

Even though no backend exists yet, UI boundaries should be clean.

Do not hardwire complex data into templates.

Create interfaces/models such as:

NewsArticle
GameUpdate
WikiArticle
WikiCategory
StoreItem

Mock providers can later be replaced by real API services.

Do NOT invent API endpoints.

Do NOT create server-side functionality.

---

# 30. Final Design Rule

At any moment ask:

"Could this interface plausibly belong to the same world shown in the Eivar Online cover artwork?"

If the answer is no, redesign it.

Fantasy should come from:

- typography
- materials
- composition
- runes
- illustration
- subtle shapes
- environmental atmosphere

NOT from excessive decoration.
